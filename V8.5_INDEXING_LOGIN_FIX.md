# V8.5 Indexing + Login Fix Notes

## Root cause found

The live GitHub Pages custom domain is `www.sarkshfoods.in`, but V8.4 generated canonical URLs, sitemap URLs and production checks for the apex `sarkshfoods.in` host.

That mismatch created two concrete risks:

1. **SEO/indexing:** crawlers could receive mixed canonical signals between apex and `www`.
2. **Login/session continuity:** customer `localStorage` and admin `sessionStorage` are origin-scoped, so apex and `www` are separate storage origins. A user crossing between them can appear signed out even when the backend session itself is valid.

## V8.5 correction

- one primary origin: `https://www.sarkshfoods.in`;
- early apex → `www` production redirect guard;
- consistent canonical/Open Graph/Twitter metadata during SPA navigation;
- product alias canonicalized to `/chilli-powder/`;
- crawl-first initial HTML for public pages;
- Brand + OnlineStore/Organization + WebSite + WebPage + Product + FAQ/Breadcrumb structured data;
- master, page, product and image sitemaps;
- robots, llms, brand/catalog and `.well-known` discovery files;
- post-deploy IndexNow submission for Bing and other participating search engines;
- resilient Apps Script fetch transport with timeout/error classification;
- safer customer/admin browser storage;
- normalized login emails and validated backend session tokens.
